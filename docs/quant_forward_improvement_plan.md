# 前向模拟改进与真实接入准备

## 2026-09-29 起的执行安排

用户要求继续模拟、持续改进方案，真实交易仍待明确接入。新批次计划观察到 2026-10-30 00:00 Asia/Shanghai，至少覆盖 30 自然日。初始建仓只能采用初始化后下一根未来 5m 边界；该时点与规则在价格出现之前冻结。9 月 28 日的旧批次不续写、不补造隔夜执行，独立保存。

本轮三个独立模拟账户各 10,000 USDT，BTC/ETH/ZEC 同一建仓时点和约 70% 初始名义底仓；不把名义金额当保证金倍增。主基准 TriEnhance 的增强上限仍为 40%，TriHold 不加仓。新增 TriEnhance20 仅把增强上限降到 20%，退出仍为 EMA200。它是降低增强敞口的预注册对照，不是已证明更好的策略。三个账户使用相同数据、费用、真实资金费、延迟记录和风险模型。

## 已实现的运行改进

- 公共行情传输与历史下载代码分离。TLS/连接池异常后关闭旧客户端并重建，限制重试次数，不泄露代理异常中的敏感字段。
- HTTP429遵守退避，HTTP418保守暂停；HTTP403/451停止主动请求，等待人工处理，不自动切换地域绕过限制。
- 不再强制本机7897代理：仅读取两个网络配置字段，可部署在合法可用的直连环境；不读取或使用交易凭证。
- 每批建立独立代码和预热输入副本，封存全部本地导入依赖及核心依赖版本。主仓库后续编辑不改变已启动批次。
- 停止时间独立于最后成功观察时间；恢复时标记补采跨度，旧事件首次观察时间保持不变。
- 全量快照以无损gzip保存，降低长周期重复曲线占用；latest.json保持便于读取的JSON。
- 真正闭合的增强持仓按逐笔买卖数量核算，部分卖出不冒充闭合交易。达到30日/10笔仅是可开始评估的门槛，永不自动授权真实交易。

## 后续改进顺序与验收

1. **连续性**：检查心跳、行情覆盖、限流退避、连接恢复和进程退出原因。任何断档都单列，不用补采伪称实时执行。
2. **独立对账**：模拟权益与逐笔现金流/公开资金费核对，保存错误、数据哈希、首次观察时间，验证三个账户的底仓一致。
3. **配对研究**：分别计算20%/40%增强相对同一持有基准的净贡献、回撤、成本、资金费、成交数和持仓暴露。至少30自然日且主动方案各10笔闭合持仓后才开始正式评价；仍不等同统计显著或可盈利。
4. **执行压力**：对独立候选增加成本、延迟、部分成交和故障窗口压力验证；不得凭同一历史窗口反复调参宣称样本外改进。
5. **真实接入准备**：先完善动态数量过滤/保证金分档、模拟订单状态机、幂等恢复、仓位对账、额度限制和人工停止。交易所真实盘口/拒单/成交偏差需独立验收。接入交易凭证、发送真实订单、设置资金规模均需用户另行明确授权。

规则或模型发生变化时创建新的候选批次，不热修改已冻结运行。自动巡检是否恢复以用户当前选择为准；系统后台运行与AI定时巡检是两件独立的事。
