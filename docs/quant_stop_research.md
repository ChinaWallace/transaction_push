# 三币策略止损优化与持续模拟

从项目根目录启动全部服务：

```bash
./scripts/quant.sh start-all
```

此命令启动原有全池模拟看板，以及三个独立的 Freqtrade 虚拟账户。所有连接配置仍由项目 `.env` 加载，使用当前代理端口 7897；独立账户配置不复制交易所密钥，运行模式被代码固定为 `dry_run`。电脑关闭或休眠期间不产生有效实时观察，也不补造历史成交。

```bash
./scripts/quant.sh status          # 原全池模拟
./scripts/quant.sh forward-status  # 三个独立研究账户
./scripts/quant.sh stop-all        # 停止全部，保留数据库
./scripts/quant.sh optimize-stops  # 校验/恢复固定的88组历史实验，不是新收益证据
```

也可单独用 `forward-start` / `forward-stop`。启动后应在看板确认状态为运行中且数据新鲜；命令返回进程号仅表示监督进程已派生。独立研究默认不替换原有50币模拟组合、优选70%上限或长期持有豁免。

## 这次保留什么

20个固定版本为4种策略家族乘5种止损方法。先以2026年1–4月、5–6月和5–6月双倍成本筛选，每家族最多保留1个，总共最多3个；再以已经看过的2026年7–9月和另采的2025全年检验。没有在压力结果出来后改选赢家。

| 版本 | 入场与退出 | 2025净收益 | 2025含浮亏回撤 | 2025双倍成本净收益 |
|---|---|---:|---:|---:|
| M4Structure | 4h趋势、1h确认、15m触发；4h趋势退出；结构低点减0.5ATR止损 | 24.62% | 21.14% | 17.52% |
| A1Fixed | 1h ADX突破；1h趋势退出；固定初始3.5ATR止损 | 24.48% | 15.24% | 15.69% |
| D55ClosedTrail | 4h Donchian55突破；通道退出；盈利2ATR后按闭合4h高点减4ATR追踪 | 11.78% | 23.60% | 8.62% |

初始10,000 USDT，仅多1x，账户预算70%，三币各约23.33%上限；基准费用为每边0.1%（包含滑点预留），压力为每边0.2%，另计真实资金费。回撤按全部5m标记价采样并包含浮亏，不是逐笔盘中极值。三种方案都没有72小时强制持仓上限，仍有各自的趋势退出和基础保护上限。

这组结果仍依赖ZEC的大幅上涨，不能当作BTC/ETH都赚钱或全币池有效的证据。2026行情已在上一版研究中看过，2025也是历史挑战；两者都不能代替真正的新行情验证。NFI X7/X8仍保留在上一版13策略对照中，本轮只对有可比趋势退出的4个家族调整止损。

## 如何看入场、退出和模拟方法

看板 `http://127.0.0.1:8891/api/quant/dashboard#stop-research`：选择实验区间，点击策略行，可看资金曲线和分页成交记录，包括时间、价格、数量、费用及触发原因。其下方“新行情独立模拟”展示账户状态、实际新模拟交易、当前止损和退出。

三种策略都以5m为引擎主周期，同时使用已收盘的15m、1h、4h数据；Fixed、ClosedTrail、Structure不利用当前5m最高价抬止损。回测在下一根5m开盘撮合；新行情模拟根据当时公开盘口进行虚拟成交，两者的滑点和资金费处理会存在差异。

实时模拟按每个策略分别配置10,000 USDT虚拟资金，不能把三个账户的70%预算或收益直接相加视为同一个组合。5秒循环检查退出，5m新闭合K线更新入场信号；超过90秒的旧信号不补开仓。入场放行前会同步保存信号、时间、报价与数量；记录失败拒绝新仓。`stop_proposed`表示策略提出的止损，实际生效价格以账本及界面`stop_loss`为准。自定义止损异常或引擎错误会锁定新开仓并保留故障文件，已有仓位仍由引擎保护退出。故障原因未查清前不要清除锁文件。

行情和盘口使用 `.env` 代理；CCXT同步HTTPS请求必须配置`httpsProxy`。初始化时发现的旧`httpProxy`映射问题已修复，三币公开盘口均已验证可达。盘口超时会记录失败次数并显示降级，不能被解释为“没有入场信号”；估值采用逐币服务端行情时间判断新鲜度。

至少累计30个自然日、每策略10笔真实前向模拟平仓后才开始评估。未达条件、数据断线和未观察时段要明确保留，不能回填成“实时成绩”。当前实现不会自动启用实盘或根据几笔盈利更换原组合。

## 可复查文件

- `reports/quant_v6/REPORT.md`：88组完整对照；`selection.json`：筛选决定；`registry.json`：历史检验状态。
- `reports/quant_v6/runs/<区间>/<策略>/`：引擎结果ZIP、配置、日志、逐笔成交、资金费、完整/预览权益曲线。
- `reports/quant_v6/integrity_seal.json`：策略、配置、源码、数据、引擎版本、原始结果的完整性绑定。它是在实际复核后补建的封存，不冒充事前登记。
- `reports/quant_v6/challenge_data/`：2025挑战原始数据及校验清单。
- `reports/quant_v6/lookahead/`：3策略切片检查，分别检查12、12、7个信号，未发现未来数据泄漏；有限检查不构成绝对证明。
- `reports/quant_v6/forward/<策略>/`：独立SQLite账本、引擎日志、首次观察K线与信号、心跳、故障锁。
- `reports/quant_v6/forward/equity_observations.jsonl`：实际观察的权益点和数据状态；`protocol.json`锁定本批模拟规则。
- `reports/quant_v6/invalidated/`：早期跳空处理缺陷试跑及配置启动失败记录，均不计入有效结果。

源码或资金口径改变后应新建实验批次，旧结果校验失败不能靠覆盖哈希绕过去。回测、前向观察、当前全池模拟是三个不同证据层级。
